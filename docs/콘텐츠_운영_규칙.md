# 콘텐츠 운영 규칙 (한 장, 2026-10-04) - 대표 승인됨(10/4 밤: ③을 일정 관리자로, 안전 수정 3종은 자동)

> 새 세션은 이 문서 → `zaoseon-site/ops/to-content.md` 최신 알림 → 앱 일정 순서로 읽는다. **기획 전에는 `docs/OSMU_일정_정리안_2026-10-04.md`(일정 원칙), `docs/먹히는_콘텐츠_분석_2026-10-04.md`(어떤 글이 반응이 났나: 자가진단 틀이 기본, 인스타 카드는 발견 채널 아님, 릴스가 발견), `docs/업로드시간_참고.md`(21시는 약한 시간대, 17~19시가 비어 있음)도 읽는다.** `docs/콘텐츠_제작_인계_2026-10-04.md`는 이날까지의 제작 기록(역사)이다.

## 1. 기준은 하나
- **일정의 기준은 관리 앱의 일정(`public/admin/data.json`의 `sns_plan`)과 Metricool이다.** 문서에 일정표를 따로 쓰지 않는다(옛 판이 된다).
- 새 글을 만들거나 옮기기 전에 그 칸을 먼저 읽는다: `python3 pipeline/precheck.py slot 2026-10-17T08:00 instagram` 그리고 Metricool `getScheduledPosts`로 한 번 더(앱 자료는 최대 3시간 늦다).

## 2. 누가 무엇을
| 누구 | 하는 일 |
|---|---|
| 대표 | 주 1회 배정표 승인, 네이버 업로드·예약 시간 수정, Metricool 예약 삭제, 댓글 확인 |
| ① | 콘텐츠 기획·제작, **비어 있는 칸**에만 예약, 예약 전 점검 |
| ③ (일정 관리자) | 일정 **이동**, 앱·자료·점검 도구, 중복 정리, 자동 점검·안전 수정 운영. 일정을 옮기는 세션은 ③ 하나 |
| ② | (역할은 대표가 확인) |

## 3. 주간 리듬
1. 월요일: ①이 **다음 2주 칸 배정표 한 장**(날짜·시리즈·운명학)을 보여 준다. 대표는 이것만 승인한다.
2. 승인된 칸은 알림 없이 진행한다. 시리즈별로 **묶어서 한 번에** 만들고 한 번에 예약한다.
3. 예약 직후 `precheck.py all`로 점검하고 걸린 것은 ③에게 알린다.
4. 2주마다 성과를 보고 시리즈를 유지할지 정한다(지금은 숫자가 작아 형식 실험 기간).

## 4. 요일 순환과 균형
월 주간 기운 · 화·금 일간 · 수 데이터(08:00)/세 지도(12:00) · 목·토 띠 · 일 모음·퀴즈·세 지도. 사주만 다루는 글은 50% 이하, 2주 안에 운명학마다 1건 이상. 같은 시리즈는 연속 2일을 넘기지 않는다. 같은 채널 같은 분에 두 글을 올리지 않고(겹치면 30분 뒤), 인스타는 하루 4개 이하.

## 5. 만들 때 지킬 것
- 샘플 서체(굵은 Noto Sans CJK KR, 왼쪽 정렬)·크기를 쓰고 다른 세션 산출물도 샘플과 나란히 놓고 본다.
- 영상은 소리가 있어야 한다(평균 -30dB보다 큼). 마지막 장은 "다음 편" 배지와 넓힌 간격(v5).
- 고객이 보는 글·화면에 "엔진·의미축·환산·데이터 릴스" 같은 내부 용어와 "11/1" 같은 슬래시 날짜를 쓰지 않는다. 날짜는 "11월 1일". AI 고지 문구는 더 넣지 않는다(AI 레이블로 충분).
- 화자는 정월. 숫자는 `content/cross_data/`에 있는 것만 쓰고 방법(무작위 3,000명, 자오선의 계산)을 밝힌다.
- 글 연결 클립·게시물 클립은 새 카드를 디자인하지 않고 **블로그 원고 이미지+캡션**으로 영상을 만든다. 블로그 대표 이미지는 가로 판(`naver/img/wide/`).
- 같은 파일을 고쳐 다시 올릴 때는 주소 끝에 `?v=숫자`를 붙이고 공개 파일이 로컬과 같은지 확인한 뒤 Metricool에 넣는다.

## 6. 점검 도구 (`pipeline/precheck.py`)
`video`(소리 크기·소리 줄·해상도) · `text`(내부 용어·슬래시 날짜·근거 없는 퍼센트) · `schedule`(같은 분 겹침·하루 인스타 4개 초과·자료 나이) · `slot`(칸이 비었는지) · `all`. 눈으로 보는 것(샘플 서체 대조, 표지 글자와 얼굴 겹침)은 사람이 한다.

## 7. 자동으로 하는 것 (승인됨) - 설계는 `docs/일정_자동화_설계.md`
같은 분 겹침은 나중 글을 30분 뒤로(같은 날, 비었을 때만), 완전 중복은 초안으로, 하루 인스타 4개 초과는 알림만. 모든 수정은 `data/schedule/changes.jsonl`에 기록, 하루 10건 상한. 날짜 이동·교체는 앱 "일정 제안" 대기열에서 대표가 한 번 승인.

## 8. 할 수 없는 것
Metricool 연결에는 **삭제와 댓글 읽기가 없다.** 중복은 초안으로 돌려(`draft:true`) 올라가지 않게 하고 번호를 `data/sns_ignore.json`에 적는다. 댓글 결과가 필요한 약속은 하지 않는다(정답이 있는 퀴즈로 설계).
